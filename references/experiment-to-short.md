# 실험에서 쇼츠까지

실험 결과를 설명하는 쇼츠를 만들 때 사용하는 작업 순서다. 특정 에피소드의 연출이나
시뮬레이터를 고정하지 않는다. 사용자가 결과의 가능성을 묻고 있으면, 영상 제작보다
그 실험을 먼저 확인한다. 제작 중 추가 질문이 오면 기존 작업을 보존하고 우선순위를 조정한다.

## 1. 질문과 실제 결과

- 첫 문장은 시청자가 바로 이해할 수 있는 질문으로 쓴다. 사용자가 정한 문구를 유지한다.
- 질문에 답할 실제 입력과 실행 결과를 확보한다. 성공한 예시만으로 “어떤 입력이든 된다”고 확대하지 않는다.
- 계산으로 설계한 모양, 물리 엔진의 운동, 목표를 따라가는 설명 애니메이션은 서로 구분한다.
- 시뮬레이터에 목표 위치를 강제로 입력하지 않았다면 그 근거도 남긴다. 초기 속도·외력·질량 분포·마찰 등 비교 조건을 기록한다.
- 실제 성공 여부는 수치와 화면을 함께 본다. 목표와의 거리만 작다고 완주한 것은 아니다.
- 원본 결과는 보존하고 입력·코드·설정·출력 해시를 기록한다. 재생에는 실제 실행한 기록만 사용한다.

원 논문·공개 코드의 가정도 확인한다. 예를 들어 기하학적인 경로 구성 가능성과
중력만으로 끝까지 굴러가는 것은 별도의 검증 대상이다. 구체적인 실패는 조건과 함께
보고하며, 한 구현의 실패를 이론적 불가능으로 단정하지 않는다.

## 2. 관찰할 변화에 맞춰 설명

각 장면을 **입력 → 연산 → 보이는 변화**로 연결한다. 계산 과정이 중요하면 실제 중간
결과를 저장해 보여 준다. 임의의 모양 보간으로 최적화나 절삭 과정을 꾸미지 않는다.

한국어만 이어 읽었을 때 자연스럽고, 한 문장에 한 동작이 들어가도록 쓴다. 기술 이름은
무엇을 하는지 보여 준 뒤 필요할 때 붙인다. 구현 조건은 결과 해석에 꼭 필요한 것만
대사로 남기고 나머지는 검증 문서에 적는다.

## 3. 음성과 장면의 시간 맞추기

1. 확정 영어 대본으로 George 음성을 생성하거나 캐시에서 재사용한다.
2. pitch를 유지한 1.05배 처리 후 실제 발화를 정렬한다. 한국어도 같은 의미 단위로 묶는다.
3. 발화 시점과 화면 표시 구간을 구분한다. 문장 사이에는 앞 자막을 유지한다.
4. 움직임을 기다려야 하는 비교 장면은 실제 결과의 1배속을 유지하고, 발화 문장을 관찰 시점에 배치한다.
5. 문장 간격만 바꿀 때는 원본 PCM과 정렬 결과를 보존한다. 무음 경계에서 문장 전체를 이동하고 자막·단어 시점도 같은 양만큼 옮긴다. 발화 중간을 잘라 시간을 맞추지 않는다.
6. 음성·대본 변경 후 timeline을 다시 만들고 해당 timeline으로 도식과 합성을 재렌더한다.

자막 cue에 오디오 시작 오프셋이 이미 포함됐는지 확인한다. 현재 `Media.align`의
문장 cue에는 0.25초가 포함되지만 `words`는 음성 파일 기준이다. 두 번 더하지 않는다.
전체 발화와 잔향이 컷 안에 들어가는지 확인하며, 무음 초안의 임시 cue를 완성본에 쓰지 않는다.

## 4. 계산 과정과 비교 화면

- Manim은 실제 발화 기준으로 60fps 도식을 만든다. Remotion은 도식·실행 결과·음성·한영 자막을 합성한다.
- Manim updater가 여러 물체를 변경하면 모두 animation의 `VGroup`에 넣는다. 일부만 animated로 선언하면 나머지가 정적 캐시에 남을 수 있다.
- 같은 Manim 임시 출력 경로를 쓰는 렌더를 동시에 실행하지 않는다. 직렬 실행하거나 작업별 `media_dir`를 지정한다.
- 처음·중간·끝을 모두 검사한다. 표시할 중간 단계를 균등하게 고르더라도 실제 계산 순서와 값을 유지한다.
- 비교 대상은 끝까지 보이게 구도를 잡는다. 카메라 이동·재생 속도·궤적 보정으로 차이를 만들지 않는다.
- 연결되는 장면은 카메라·벽·조명·재질 상태를 공유한다. 단순 crossfade로 불연속을 덮지 않는다.
- 투명도 전환의 직전·도중·직후를 검사한다. `depthWrite`, 렌더 순서, opaque 전환이 밝기나 가림을 갑자기 바꾸지 않는지 확인한다.
- 렌더 배경과 합성 배경은 최종 디코딩된 RGB도 비교한다. 소스 색 코드가 같아도 색공간·범위 변환으로 사각 경계가 생길 수 있다. 문제를 확인한 변환만 수정한다.

## 5. 별도 썸네일과 게시글

영상의 한 프레임을 그대로 썸네일로 대체하지 않는다. 실제 캐릭터·소품·모양을 참고해
별도 구도를 만들고, 짧은 제목과 한 가지 시각적 질문을 남긴다. 시리즈는 재료와 스타일을
공유하되 각 편의 현상이 구별되게 만든다.

래스터 이미지가 필요하고 호스트에 이미지 생성 도구가 있으면 그것을 사용한다.
도구가 제공하지 않는 모델 버전을 추측해 기록하지 않는다. 프롬프트·원본·참고 이미지·수정
이력은 에피소드 폴더에 보존한다. 그림 속 홈·레일·광선 같은 장식이 실제 원리를 다르게
설명하면 수정한다. 생성 커버는 실행 증거로 사용하지 않는다.

1080×1920 전체, 중앙 3:4, 중앙 4:5와 휴대폰 크기에서 제목·대상·차이가 읽히는지 확인한다.
게시글은 자연스러운 한국어 본문 → 영어 본문 → 공통 해시태그 최대 5개로 만든다.

## 6. 검수와 전달

대표 프레임 검수 다음에는 연속 재생으로 전환과 속도를 확인한다. 다음 항목은 따로 기록한다.

| 확인 | 근거 |
|---|---|
| 입력·실행 결과 보존 | 원본 파일과 해시, 실제 사용한 설정 |
| 매체 검사 | 해상도·fps·오디오·길이·전체 디코딩 |
| 자막 검사 | 현재 timeline, 줄 수·폭·발화 끝의 컷 범위 |
| 시각 검수 | 사건 전·중·후 프레임과 연속 재생 구간 |
| 음성 청취 | 실제 들은 범위와 수정 사항; 안 들었으면 미실시 |
| 전달 확인 | 로컬 사이트에서 영상 재생·다운로드 링크 확인 |

`python -m shorts_app.check_render`로 매체와 timeline 범위를 검사할 수 있다.
자동 검사는 미관·발음·물리적 타당성을 승인하지 않는다.
[검수 양식](../templates/experiment-review.md)에 실제 근거를 채운다.

새 고유 파일명으로 로컬 검토본을 만들고 이전 버전을 보존한다. 완성 영상·별도 썸네일·
게시글을 함께 연결한다. Drive 업로드는 기존 사용자 승인 범위와
[전달 절차](../docs/DRIVE_DELIVERY.md)를 따른다. 이미 받은 승인을 다시 묻지 않는다.
공개 게시나 권한 변경은 별개의 행동이다.
